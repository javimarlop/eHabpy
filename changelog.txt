- Dissolve operation updated and implemented in python
- Bug fixed in similarity indices computation when using a mask
- Updated column names and new column added to hriresults
- Updated script to process subpas automatically 
- Documentation added to each script
- Readme updated with OS installation instructions and tutorial
- New fixed seed map for each PA as an input for the first segmentation step to improve consistency of resuts when running it under different GRASS GIS versions.
- New options in 'moranvar_plots.R' added
- New script for using the median values to find the optimal segmentation threshold and the final HFTs
- New script for using the median values of the reference HFTs to find similar landscape patches
- New script for computing the THDI
- Segment IDs (segm_id) are now area ID + threshold index + zero-padded segment number, so they no longer collide between thresholds or areas and are the same on reruns (previously area ID + segment number + random number).
- Resuming with FORCE_RESTART = False removes the leftovers of an interrupted area before processing it again.
- segmentation_pca_par.py starts from the PERMANENT mapset, creates its output folders and stops with an error (instead of hanging) when a GRASS command fails.
- moranvar_plots.R: the optimal threshold is interpolated on the evaluated threshold values (not row positions), always maps to an evaluated threshold (optim = 2 could give 0) and overall_optim_thresholds.csv keeps one row per area instead of appending duplicates.
- New SIMIL option in config.py (read by moranvar_plots.R): SIMIL = 3 cuts the HFT dendrogram at 25, 50 and 75 % of its maximum height without an upper limit and writes each classification to results/p25, results/p50 and results/p75.
- Radar plots draw every HFT in numeric order with the same colours as the HFT map (previously at most 9 HFTs, ordered as text); the map legend is also in numeric order.
- With SIMIL = 3 the HFT output files also carry the cut in their name (e.g. park_segm_1_5_p25_class.shp), and moranvar_plots.R writes results/processing_metadata.txt with the config.py options and its own options (optim, upper) used for the run.
- New segm_optim/setup.py: creates the GRASS GIS project, named after the study area file in pa/, from the GeoTIFFs in ../inVars (with their CRS), imports them and the study area in pa/ into PERMANENT, writes palist.csv and fills the REQUIRED options of config.py (including RESOLUTION and the NoData values) from the data.
- segmentation_pca_par.py uses the first variable of ENV_VARS0 (instead of a fixed 'precip') to delimit the valid pixels, which now are those with data (previously those >= 0).
- ehab_segm_core.py takes the pixel size from RESOLUTION in config.py instead of a fixed 10 m.
- The results of moranvar_plots.R are saved in results/<STUDY_AREA> (e.g. results/guajares, with results/guajares/p25, p50 and p75 when SIMIL = 3), so the results of each study area are kept apart. FORCE_RESTART only removes the results of the study area being processed, and csv/shp/tiffs are started from scratch when they belong to another study area (recorded in csv/study_area.csv).
- segmentation_pca_par.py merges the segments smaller than minarea with the most frequent segment within 3 km in memory (numpy/scipy) instead of creating three raster maps per segment and joining them with r.patch, which failed with "Too many open files" when masked inputs leave thousands of isolated fragments and took about an hour per threshold. The result is the same cell by cell (checked on the Guajares data, 4076 small segments). The variables must have a projected CRS in meters (checked by setup.py).
